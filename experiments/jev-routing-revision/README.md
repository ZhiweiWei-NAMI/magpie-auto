# Jev 路由修订与诊断

这次修订针对旧实验暴露的执行边界、上下文压力与会话延续问题。旧十二题结果保留在 [jev-cache-20261012](../jev-cache-20261012/)，不由本次结果覆盖。两题诊断为事后选题，不能作为无偏的新 benchmark。

10051 三组均通过；7236 三组均在 600 秒超时且为空补丁。Auto 的 7 次 Jev 都发生在 7236，一次压力触发分成七批；用量 **60,932 输入 / 2,739 输出**，API 耗时 **8.448 秒**，决定保留，没有实际替换。A/B/C 的 DeepSeek 请求为 **56 / 108 / 86**；其中 A 1、B 1、C 3 次缺少 usage，均保留为不可观测。C 的其中两次 HTTP 200 流未返回 usage，不能把它们算成零或断言服务没有消耗。

三组均解决的 **10051 单题**，A/B/C 耗时 **214.04 / 402.01 / 562.16 秒**，未命中输入 **196,018 / 297,917 / 262,022**，输出 **22,997 / 62,729 / 36,946**。A 相比 B 未命中少 **34.2%**、输出少 **63.3%**、时间少 **46.8%**。但该题 A 没有调用 Jev；压力校准与原生压缩触发不同，且只有一次运行，不能把这些差异归因于 Jev 判断或外推为总体提升。

每组均 15 次 DeepSeek 请求、零任务级 Jev；它们验证短任务可以省掉决策开销，不验证复杂路由的稳定性。样本不足以估计可靠 P95 或宣称显著优势。另做了 [同一微型决策状态三次调用](decision-repeats.json)：三次均选既有 implementation_child，选择概率 **0.98–0.99**、confidence **0.97–0.98**；重要性 score 的最大变化 **0.03**。这是微型决策抖动观测，不替代完整任务重复。

**M7 发布版原生协作**：[从 GitHub 安装后的真实运行](native-continuation-reuse-installed/result.json) 完成一个子代理、两次激活和两次回收，Jev 实际选择 reuse，测试通过。耗时 **181.36 秒**，主代理 17 次、子代理 13 次 DeepSeek，Jev 5 次，包含三次拒绝后重新提出的候选。所有执行请求的系统、工具定义和追加顺序保持稳定。该强制协作探针验证机制，不用来证明拆分小任务划算。

**M4 缓存剩余问题**：发布版续用子代理的第二次激活首请求输入 **9,607**、命中 **6,784**、未命中 **2,823**。但同一会话其他请求仍有零命中；[账号对齐明细](cache-affinity-observation.json) 显示，回到旧账号时命中量贴近它上次的输入，新账号通常只有 0–384 命中。这支持账号亲和性影响缓存的推断，尚不是受控因果试验。8788 共享运行版本未改动。缓存写入与 Jev 缓存不可观测，价格未提供可靠依据。

发布版 [上下文探针](native-continuation-context-release/result.json) 7 次执行、7 次 Jev，完成两次真实替换并通过测试，33.94 秒；系统与工具不变，两次历史前缀变化如实记录。压力阈值刻意调低，仅用于验证应用链路。

**全账范围**：上述六次 SWE 诊断共 257 次模型请求，跨模型工作量下界为 **3,558,776 输入 / 425,432 输出** token（5 次 usage 不全）；本目录记录的全部开发探针、三次配置编译、三次固定决策重复、九次短任务合计 **218 次，1,813,166 输入 / 79,958 输出**，包含失败探针。两部分共 **475 次**，工作量下界 **5,371,942 输入 / 505,390 输出**。不同模型 token 合计只表达工作量；不计算未获可靠依据的美元费用。详见 [探针账本](probe-summary.json) 与 [探针逐请求](probe-requests.csv)。

这些是验收与比较维度，不是已经全部改善的结论。成本、延迟、质量可能存在取舍；包含某个固定策略不等于选择器知道何时选择它，也不消除决策成本。

本次按 [OpenCode Jev 接口](https://opencode.ai/v2/docs/console/models#jev)、[原子决策说明](https://docs.typesafe.ai/introduction)、[模型限制](https://docs.typesafe.ai/models)、[Jev 1.13 已知弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)、[score 等级](https://docs.typesafe.ai/primitives/score) 与 [confidence 含义](https://docs.typesafe.ai/confidence) 核对。官方仍将 `jev-1.13-free` 标作限时免费；不是永久可用保证。实际请求均走专用 System One，价格与缓存字段未提供，不补造。

## 一句话配置与边界

控制台策略框的中文输入已用真实 Jev 编译：自动、固定单代理、再切回自动均成功。三个配置调用分别耗时约 1.13 / 0.51 / 0.52 秒；完整输出、usage 和分布见 [configuration-probes.json](configuration-probes.json)。重复的自动指令之间插入过另一指令，因此第三次不是缓存命中试验。两次相同指令的软权重有轻微差异；执行会话读取固定快照，避免每轮重新解释。

用户输入调整的是允许候选的初始偏好及保守程度，不是修改 Jev 参数，也不是绕过模型/工具权限。Jev 不生成自由文本方案：主执行模型提出任务，Jev 决定委派价值、配置与会话复用，dsh 执行。模型、effort、职责和工具边界显式给定，当前实际只允许 DeepSeek Flash High。

相同配置再次保存也实际验证过：4.8 毫秒返回完全相同的已保存决策，没有新增 Jev 调用，见 [configuration-reuse.json](configuration-reuse.json)。配置的 3,214 输入 / 366 输出 token 单列计入，不在每个任务中重复收费或重复计数。

## 真实流程探针

[同一原生子代理两次完成](native-continuation-native-store/result.json)：一个子代理、两次激活，代码测试通过，121.65 秒。第二次激活首请求的 system/tools/append-only 均保持，输入 11,513、命中 6,912、未命中 4,601、输出 303 token。该探针的第二次激活由主代理直接调用 send_message，证明原生延续可用；不冒称已验证 Jev 选择 reuse。

[上下文应用探针](native-continuation-context-valid/result.json)：6 次执行请求、7 次 Jev、两次真实替换，31.88 秒，代码测试通过，并独立检查末尾 `A\t  B` 约束。压力阈值刻意设为 4096，不用于证明性能收益。真实请求与事件分别见该目录 requests.json / events.json。

## 两题三组诊断

题目在新求解前固定：10051（原三组通过但 Auto 输出偏多）、7236（原 A 失败、B/C 通过）。这是根据已知结果选择的机制诊断，不估计泛化收益。配置和实际执行顺序保存在 [diagnostic](diagnostic/)。三组使用相同 High 执行模型、初始仓库、CPU/Docker 环境、原生工具、任务总预算与完成标准；模型调用经过同一 Magpie/WorkBuddy 链路。保留所有失败与超时。

诊断对应插件 `50408ca`，发布版探针与三轮短任务对应代码 `eaa6ead`。后者修复工具描述变化并补充路由观测状态，不回填或覆盖诊断。A 采用实测输入校准，B/C 仍用原生估算触发压缩；这不是“对已经同样校准的原生基线，仅加 Jev”的消融。运行版本是工作源码构建，构建 VCS 状态也保留在配置中。

```bash
python experiments/run_routing_revision.py
python experiments/grade.py --root experiments/jev-routing-revision/diagnostic --label routing-v03 --watch
python experiments/summarize.py --root experiments/jev-routing-revision/diagnostic --trial-dir /mnt/data2/weizhiwei/magpie-auto/bench-runtime/routing-revision/swe-trials
```

求解智能体仅见 base_commit、issue 和本地模型服务；官方答案只供隔离评测器使用。重跑时给 `run_routing_revision.py` 传入全新的 `--results-dir` 与 `--trial-dir`；`--plugin-dir` 指向要测的 Git 工作区，脚本记录该实际提交。精确重现本轮诊断需插件提交 `50408ca`，而非后来修复的发布标签。禁止覆盖已有运行目录；完整重现旧十二题应使用当时 Magpie 提交 ae23c24 与插件 v0.2.2，而不是把新插件冒充旧版本。

## 缓存与开销

A 的 71 次 Jev 请求均返回 HTTP 200、实际模型 `jev-1.13-free`，API 内部耗时合计 56.09 秒，代理往返合计 56.26 秒。官方仍将此标识列为[限时免费](https://opencode.ai/v2/docs/console/models#jev)。这里没有自动重试、充值或付费模型切换。

A 的 369 次主代理和 104 次子代理请求都保持稳定的系统提示与工具定义；同一会话的历史均按前缀追加。压力决策全部选择 keep，没有实际上下文替换。B/C 分别有 55/56 次原生摘要请求，其消耗已计入 DeepSeek 总量。

三组全部解决的五题为 10051、10081、5262、5631、5809。这是质量相近的补充比较，主结果仍包含原定全部十二题的失败。见 [quality-matched.json](quality-matched.json)：

| 组 | 五题耗时秒 | DeepSeek 输入 | 未命中 | 输出 | Jev 输入 / 输出 |

| A | 815.90 | 1,876,892 | 601,244 | 111,286 | 40,021 / 407 |

A 在这五题中比 B 少 12.7% 未命中 token，但输入多 21.5%、输出多 27.9%、耗时多 6.7%；比 C 的未命中只少 0.5%。稳定历史保住了部分缓存复用，但本次没有证据证明 Auto 降低整体消耗或费用，整体解决率也未提高。短任务优先使用单代理；需要独立调查的任务可以试用 Auto，但本次只有一位调查者完成，两位在同一任务中失败，尚不足以证明协作收益。

Jev 上下文筛选分批、完整来源及长文本尾部保留有短回归验证，独立 API 的 noul/score 有实际返回。正式十二题均未触发 select，所以真实原生压缩事务中应用 Jev 筛选的效果仍未验证，不把代码路径存在当作实测成功。

## 条件与局限

运行配置见 [run-config.json](run-config.json)，顺序见 [execution-order.json](execution-order.json)。三组采用同一任务级上限：600 秒、64 次全部上游模型调用、最多两个子代理和两个并发子代理。C 实际没有调用子代理，没有为凑数强制拆分任务。Auto 当前只在会话开始选择调查方式，调查结果收回后主代理才写代码；不声称已有动态全程任务调度。

所有组上下文压力均为估计 24k、保留最近 8k，低于 dsh 默认 0.8 比例；结论不能直接推广到默认配置。原生 dsh 配置 thinking disabled/off，原有 Magpie 连接实际覆盖 reasoning_effort=low，三组相同；接口仍有 reasoning token，完整输出用量保留。

远程缓存未清空，8788 当前运行版本为 least_inflight，同一会话的账号仍轮换。转发会话标识未产生账号绑定。请求记录使用匿名账号标签与实际缓存统计，没有假定缓存隔离或固定账号。只有一个项目、十二题、每组一次运行，不构成普遍性能结论。

求解容器使用内部 Docker 网络，只能经本地 relay 访问同一模型链路，外部源码站访问检查失败。Git 对象仅保留原始 base_commit 和树，无未来引用、对象或 reflog。官方参考补丁只留在私有 evaluator，不挂载给求解容器。各组工作区独立、干净，CPU 4 核、内存 8G、runc，无 GPU；官方评测采用两个 CPU worker。

首次下载、工作区准备、求解和评测分别记录。前九个镜像已由开发试跑缓存，其首次下载时间未提供；最后三个按需下载，三组共享同一准备条件。开放网络试跑发现求解模型下载后续发行版源码或测试，因此 [pilot-open-network](pilot-open-network/) 保留成绩和用量，但不进入正式比较。pilot-output4096、pilot-unbounded-jev、preflight 同样单独保留；没有根据试跑结果改变十二题题单。

## 复现与使用

独立插件已通过原生 dsh 安装和真实编程任务验证，见 [安装验证](smoke/installed-plugin/)；[双子代理小任务](smoke/native-two-children/) 留有完整原生结果回收和代码测试。服务器进入任务目录后运行：

```bash
/mnt/data2/weizhiwei/magpie-auto/run-auto '你的编程任务'
```

复现实验请采用新结果目录与新任务 home，并在无其他本部署模型请求时运行。脚本复用本服务器已有连接与私有 evaluator，不包含任何账号凭据。依赖及官方 harness 固定版本见 ../requirements.txt；外部机器需准备同样版本的 native dsh、Magpie、CPU Docker 和私有 Verified evaluator 数据集。

```bash
cd /mnt/data2/weizhiwei/magpie-auto-repo
BENCH_PY=/mnt/data2/weizhiwei/magpie-auto/bench-runtime/venv/bin/python
NEW_RESULTS=/mnt/data2/weizhiwei/magpie-auto/bench-runtime/new-results
NEW_TRIALS=/mnt/data2/weizhiwei/magpie-auto/bench-runtime/new-trials
CUDA_VISIBLE_DEVICES= USE_TF=0 "$BENCH_PY" experiments/run_compare.py --limit 12 --results-dir "$NEW_RESULTS" --trial-dir "$NEW_TRIALS"
CUDA_VISIBLE_DEVICES= USE_TF=0 "$BENCH_PY" experiments/grade.py --root "$NEW_RESULTS" --label repeat
"$BENCH_PY" experiments/summarize.py --root "$NEW_RESULTS" --trial-dir "$NEW_TRIALS"
```

原始追加式会话日志留在服务器 bench-runtime/trials-controlled-jev；公开材料仅导出必要的原生工具、压缩和计量证据。完整 Go 验收、短回归及未完成的 GUI/浏览器检查边界见 [validation-jev.md](../../docs/validation-jev.md)。
